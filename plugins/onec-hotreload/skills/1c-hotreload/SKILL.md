# 1C:Enterprise Hot Reload Skill

Этот навык предназначен для применения изменений BSL-кода в живой среде 1С:Предприятие (как на сервере `rphost`, так и в тонких клиентах `1cv8`) без перезапуска процессов, без разрыва сеансов и без закрытия экранных форм.

## Когда использовать
- Пользователь просит применить правки BSL «на лету» / без перезапуска сеанса / без выбивания пользователей.
- Требуется изменить текст, поля, условия запроса 1С или алгоритм его постобработки в живой сессии.
- Требуется верифицировать поведение BSL-модуля на живом стенде 1С без длительного перезапуска толстого/тонкого клиента или кластера.
- Необходим автоматический dev-loop: авто-сохранение и мгновенное обновление логики через `watch`.

---

## Быстрый старт: валидация окружения и приёмка

Перед выполнением любых операций с памятью или базой запустите самодиагностику:

```bash
# 1. Диагностика окружения хоста и доступности стенда
./hr --profile <profile.json> doctor --json

# 2. Автоматический сквозной смоук-тест hot-swap (A -> B -> верификация сессии)
./hr --profile <profile.json> test-live --json
```

## Основные команды CLI `./hr`

### 1. Горячая модификация запросов и констант (`server-poke-str`)
Хирургически заменяет строковые константы и тексты запросов в куче `rphost` под безопасной точкой (`safe_point`):

```bash
# Точная замена строки в куче сервера (запрос выполняется в родной сессии с RLS и транзакциями)
./hr server-poke-str "СТАРАЯ_СТРОКА" "НОВАЯ_СТРОКА"

# Если новый текст запроса короче — флаг --pad автоматически дополнит его пробелами
./hr server-poke-str "ВЫБРАТЬ Номенклатура, Количество ИЗ ..." "ВЫБРАТЬ Номенклатура ИЗ ..." --pad
```

### 2. Серверный Hot-Swap методов (`server-swap`)
Перенаправляет вызовы методов серверного модуля (`Server`) на донорский контекст новой генерации через диспетчер `hrhook2`:

```bash
# Проверить список серверных контекстов в rphost
./hr server-status --module <ModuleName>

# Выполнить горячую замену серверного модуля
./hr server-swap --module <ModuleName> [--target-ctx <ADDR>] [--donor-ctx <ADDR>]

# Включить / выключить / снять перенаправление
./hr enable
./hr disable
./hr detach
```

> [!IMPORTANT]
> **Ограничение `Новый Запрос` при `server-swap`**: создание нового объекта `Новый Запрос` из подмененного `this` чужой генерации падает из-за несовпадения TLS менеджера метаданных.
> **Паттерн разделения**:
> - Текст, условия и поля запроса меняются через `server-poke-str` (в родной сессии).
> - Алгоритмы постобработки (циклы, формулы, ветвления) меняются через `server-swap`.

### 3. Клиентский Hot-Swap (Thin Client `1cv8`)
Заменяет скомпилированный байткод и литералы общего модуля (`ClientManagedApplication`) прямо в памяти запущенных тонких клиентов без закрытия открытых форм:

```bash
# Проверить статус клиентских модулей
./hr client-status --module <ModuleName>

# Применить замену модуля ко всем активным клиентам (или конкретному PID)
./hr client-swap --module <ModuleName> [--target <PID>]
```

### 4. Автоматический режим (`watch`)
Автоматически определяет область действия модуля по его XML-дескриптору (`Server`, `ClientManagedApplication` или смешанный), выполняет обновление базы и синхронно применяет hot reload к `rphost` и всем клиентам:

```bash
./hr --profile <profile.json> watch --dir <config_dump_dir> --module <ModuleName>
```

## Правила безопасности и ограничения (Fail-Safe)

1. **Никаких `pkill -f`**: завершать процессы только по конкретным `PID`, найденным через `ent_clients()` или `pgrep`.
2. **Safe-point дисциплина**: любая запись в память процессов выполняется только после `SIGSTOP`, проверки instruction pointer всех потоков вне `bsl.so`, с последующим `SIGCONT`.
3. **Безопасность строк `StringValue`**:
   - Строки $\le 7$ символов (SSO) копируются инлайн в `+0x20..+0x38`.
   - Длинные строки кучи (`core::string`) копируются в целевой буфер процесса (`target_ptr + 4`) с проверкой длины и счетчика ссылок.
4. **Секреты**: пароли баз данных не передавать в аргументах команд; передавать только имя переменной окружения через `passwordEnv`.
5. **Git**: не выполнять `git commit` или `git push` без явной команды пользователя.
